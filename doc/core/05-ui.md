> 5 个页面。店铺为中心，操作为主线。禁止引入 polabel2 那种多层导航和复杂操作动线。
> 共享视觉基元、实施顺序与逐页验收见同属宪法层的 `05-ui-components.md`。

## 1. 技术栈（无构建步骤，单二进制部署）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端模板 | Go `html/template` | 服务端渲染 HTML shell |
| 样式 | Tailwind CSS CDN | `<script src="https://cdn.tailwindcss.com">` |
| 交互 | Alpine.js CDN | `<script defer src="https://cdn.jsdelivr.net/npm/alpinejs@3/dist/cdn.min.js">` |

- 位置：页面头部右侧

```

```
"保存并测试"：先 `POST /api/accounts` 写回配置（生成 `config.yaml.bak`）→ 自动调 `POST /api/settings/test-connection?account=:id` → 成功显示绿色 toast，失败显示红色原始错误。新增账号属**结构性变更**，保存后顶部出「需重启生效」横幅（见 §6 Tab B）。

#### 按钮：测试连接（每账号一个）
- 样式：secondary 小号
- 点击：`POST /api/settings/test-connection?account=:id` → toast 结果（含延迟 ms）

- **自动测试连接续租**：编辑账号的 `connection_check.cron/enabled`，由本机 Cron 真实调用 OpenAPI Token 获取并主动续租；不属于业务 endpoint，不展示在同步配置的业务 Cron 表。
- **店铺目录**：点击“立即刷新目录”调用 `POST /api/accounts/:id/stores/sync`，服务端只解析该账号唯一 `is_store_source` endpoint。其 Cron、限流与启停继续在同步配置管理。

#### 按钮：同步店铺（每账号一个）
- 样式：secondary 小号
- 作用：调领星"获取店铺列表"接口，更新已绑定店铺表
- 点击：spinner + "同步中…" → 完成后刷新店铺列表

#### 按钮：删除账号（每账号一个）
- 样式：`text-red-600 hover:underline text-sm`（ghost 链接式）
- 点击：**二次确认弹窗**："删除账号 sc_us，确认？" → 确认后 `DELETE /api/accounts/:id`
- **拦截规则**：若该账号下仍挂有接口，后端返回 `409`，前端弹红色 toast「该账号下still有 N 个接口，请先删除接口」，**不级联删除**。删除成功属结构性变更 → 出「需重启生效」横幅。

## 5. ~~页面二：概览（`/`，首页，原「同步中心」）~~ —— 已删除（2026-08-08）

> **删除原因（用户决策）**：原「概览」页只读**进程内存**状态（`GET /api/status` → `registry.Statuses()`），
> 进程一重启所有格子归零、显示为「空闲」，与磁盘上 `ls_*` 表的**真实数据新鲜度无关**；顶部「今日写入/今日错误」
> 也是内存计数（`worker.todayRecords/todayErrors`），每次部署即失真。它能回答的问题 `/logs`（查 `sync_tasks`：
> 有历史、可按状态筛、重启不失忆）都答得更准。
>
> 那张「状态矩阵」原设计是 `数据类型 × 店铺` 交叉，但本项目 worker 是「账号+接口」一对一，行键已唯一决定列，
> 退化成 `endpoint × account` 的半空表（N 行 × M 列里只有 N 格有值）。加上 `CoverageDimension`/渠道矩阵是
> **CLAUDE.md §2 明令禁止继承**的 polabel2 概念，故整页删除。
>
> 概览唯一不可替代的职责——「哪张表没有近期数据」——已改由**数据源页（§8）的「最后写入」列**承担
> （`db.TableLastSync` = 该表 `MAX(synced_at)`，来自 DB，重启不失忆）。
>
> **落地**：删除 `web/templates/sync_center.html` 与 `app.js` 的 `syncCenter()` 组件；`pageIndex` 改为
> `302 → /sync`；`listItems` 去掉「概览」项；渲染测试改渲染 `sync_manage`。路由 `GET /{$}` 保留但只做跳转。

## 6. 页面三：同步配置（`/sync`，原「同步管理」）

### 目标：手动触发 + 管理定时调度 + 正式报表检验 + 添加接口，同一页面，四个二级 Tab

```
同步配置
[手动同步]  [定时调度]  [报表检验]  [添加接口]   ← 四个二级 Tab，默认在"手动同步"
```

> 定时调度表为**内联直接编辑**（用户要求，无独立「编辑」按钮）：直接改 cron / 限流（桶 / ms）/ 店铺白名单 sid / 同步日期策略，或切换「启用」勾选 → 该行进入 dirty（整行 `bg-amber-50 ring-1 ring-inset ring-amber-200` 高亮）→ 行右出现「保存 / 取消」。保存沿用 `PUT /api/endpoints/{name}`，仅更新本行基线（不整表 reload，避免连带丢弃其他行未保存编辑）。每行 dirty 判定复用店铺选择的 baseline 快照模式（`scheduleBaseline[name]`）。

### Tab A：手动同步

```
┌─── 触发一次同步 ─────────────────────────────────────────────┐
│                                                              │
│ 数据类型   [销售订单 ▾]                                      │
│ 店铺       [美国自营店 ▾]  ☐ 全部店铺                       │
│ 日期范围   [2026-07-30] 至 [2026-08-06]（仅本次）            │
│                                                              │
│                                    [立即同步]                │
└──────────────────────────────────────────────────────────────┘

正在运行（2 个）：
  ┌─────────────────────────────────────────────────┐
  │ 销售订单 / 美国自营  第 3/? 页   已写入 285 条  [取消] │
  │ FBA库存  / 加拿大    第 1/? 页   已写入 0 条   [取消] │
  └─────────────────────────────────────────────────┘
```

#### 按钮：立即同步
- 样式：primary 标准
- 禁用条件：未选数据类型 / 日期填写不完整或不适用
- 点击：按选中接口分别调用 `POST /api/sync/:name`；日期只覆盖本次任务

#### 日期范围规则
- 范围接口可填起止日期；快照接口不显示可用日期策略
- 单日接口只能选择同一天；跨日需按日顺序执行

#### 按钮：取消（每个运行中任务）
- 样式：`text-xs text-red-600 hover:underline`
- 点击：二次确认 → `POST /api/sync/:id/cancel`

### Tab B：定时调度

```
⚠ 配置已修改，账号/接口路径类改动需重启生效          [立即重启]   ← 需重启横幅（有结构性未生效变更时才显示）

数据类型        Cron 表达式        同步日期       状态     上次执行     操作
销售订单        */10 * * * *       ● 启用   3 分钟前     [编辑] [禁用]
FBA 库存        0 */2 * * *        ● 启用   2 小时前     [编辑] [禁用]
广告日报        30 1 * * *         ● 启用   昨天 01:30   [编辑] [禁用]
结算报告        0 3 * * *          ○ 已禁用  —           [编辑] [启用]
```

> 「报表检验」和「添加接口」均不嵌在定时调度内容中，分别作为 Tab C、Tab D。

#### 需重启横幅（顶部，条件显示）
- 出现条件：任一写操作返回 `need_restart: true`（新增/删除账号、新增/删除接口、改 path/method/table/DB）
- 样式：`bg-amber-50 border border-amber-200 text-amber-800 px-4 py-2 rounded-lg`
- 「立即重启」按钮：`POST /api/settings/restart` → 进程 `syscall.Exec` 原地重启（PID 不变，Supervisor 无感）→ 前端 3 秒后自动重连轮询 `/api/status`

#### 日期策略（每行）
- 范围接口编辑「近 N 天」并保存 `window_days`
- 单日接口编辑「T-N」并保存 `date_offset_days`
- 快照接口显示「当前快照」，不提供日期输入

#### 按钮：保存（每行）
- 点击：保存内联字段：`[cron 输入框] [桶容量] [限流间隔ms] [店铺白名单] [日期策略] [保存] [取消]`
- Cron 输入框旁有提示：`*/10 * * * * = 每10分钟`
- 保存：`PUT /api/endpoints/:name` → 这些字段（cron/rate/store_sids/window）属**非结构性**，返回 `need_restart:false`，**热加载立即生效**，绿色 toast「已生效」
- 「店铺白名单」多选该接口所属账号在 `ls_stores` 里的店铺；不选=全部店铺（对应 `store_sids` 空数组）；仅对 `iterate_by_store` 接口可编辑

#### 按钮：禁用 / 启用（每行，状态切换）
- 禁用态→变灰；启用态→正常
- 点击直接切换 `PUT /api/endpoints/:name`（只改 enabled）→ 热加载生效，无需确认（非破坏性操作）

### Tab C：报表检验

正式 Amazon 报表与普通 JSON API 的执行链路不同，因此单独管理，但仍留在 `/sync` 页面内，不增加一级导航。

只展示已完成解析、独立原始表和对账合同的 FBA Customer Returns 与 FBA Customer Shipment Sales。未完成真实合同的报表类型不得提前显示空壳选项。

顶部批量区一次选择账号、区域、多个店铺、报表类型、每日执行时间和回看天数；店铺选项复用本地 `ls_stores` 的 `sid/seller_id/marketplace_id`，不得要求逐店重复手填。缺少 seller 或 marketplace 的店铺直接标错，不猜值。

下方紧凑表每行显示：报表类型、账号/店铺、执行时间、回看天数、启停、最近结果、数据库缺少、报表缺少和值不一致。详细 task/document ID 放行展开区。

### Tab D：添加接口

> 从「定时调度」Tab 底部独立出来，成为 `/sync` 的第四个二级 Tab。
> 深链 `/sync?tab=add` 直达（旧 `/sync?add=1` 仍兼容）。两条添加路径，主路径无需手填合同：

**主路径 · 从清单添加**（`catalog.templates`，来自 `GET /api/catalog`）：挑一个模板 → 选账号 →「启用」，
不用手填表名/路径/参数；已启用的账号在下拉里置灰。走 `enableCatalog(key)`。

**高级 · 手动填写接口合同**（默认折叠，`advancedAdd`）：清单里没有的接口才用，**目标表须先建好**。展开后：
```
标识 name  [____________]   （字母下划线，全局唯一）
显示名     [____________]
账号       [账号 ▾]
Path       [____________]   （从领星文档"API Path"原样抄）
方法       [GET ▾]        目标表 [____________]（ls_ 表须先建好）
唯一键     [____________]   （逗号分隔，如 order_id 或 sid,date）
Cron       [____________]
桶容量 [__]  间隔ms [___]  多店铺间隔ms [___]  回看天数 [__]
按店铺迭代 ☐   店铺参数名 [____]   额外参数 extra_params（JSON，可空）[____]
                                                        [保存]
```
- 两条路径都落 `POST /api/endpoints` → 新增接口属**结构性变更**，返回 `need_restart:true` → 顶部横幅提示重启后生效

## 8. 页面五：数据源（`/datasources`）

### 目标：让同步机运维人员知道“同步了什么，数据有多新”

```
数据源                           ← 这里的数据是领星同步机写入的，只读

数据类型        表名              记录总数    最近同步时间     覆盖店铺
销售订单        ls_sales_orders   1,234,567   3 分钟前        5/5 店铺
SC FBA 库存     ls_fba_inventory    45,678    2 小时前        4/5 店铺
广告日报        ls_ads_daily       890,234    昨天 01:30      5/5 店铺
结算报告        ls_settlements     234,567    今天 03:00      5/5 店铺

```

点击任意一行 → 展开字段结构（内联展开，不跳页）。字段**从目标表实时读取**，调 `GET /api/datasources/:table/columns`（读 INFORMATION_SCHEMA，返回列名+类型+是否主键），不写死：
```
▼ 销售订单 ls_sales_orders
   order_id       VARCHAR(64)  主键
   account_id     VARCHAR(32)  店铺 ID
   order_status   VARCHAR(32)
   asin           VARCHAR(16)
   sku            VARCHAR(128)
   quantity       INT
   amount         DECIMAL(14,4)
   currency       VARCHAR(8)
   purchase_date  DATETIME
   gmt_modified   DATETIME
   synced_at      DATETIME
```
- 展开时若接口返回空或报错，显示「未能读取字段结构」占位，不静默空白。
- 列表顺序与 MySQL 表定义一致（ORDINAL_POSITION 升序）。

## 9. 页面六：数据集字段（`/dataset-fields`）

页面固定为数据源第 5 个一级导航，并分为两个同级切卡：`数据表配置`、`新增下游项目`。下半部分仍保留原始 `ls_*` 数据源列表。

### 目标：配置系统数据表，再登记读取下游项目

```text
[数据表配置] [新增下游项目]

Listing 日维指标表  ID: listing-daily-v1
业务字段                              固定字段
销量 / 库存 / Performance / 广告       店铺、渠道、ASIN、SKU、业务日期、更新时间、临时标记、验证状态

下游项目          可读取数据表          Token ID    Bearer Token    店铺范围
polabel2          listing-daily-v1,... tok_xxx     xxxxx...        12534, 12535
```

- `数据表配置`先显示数据表目录。每项展示类型（日维、明细、快照）、来源 `ls_*`、粒度和固定 SQL 结构；选择一项后才显示该表字段配置。未发布的表版本可从左栏添加字段到右栏并首次发布；版本发布后左右字段均锁定。字段增加、删除、改名或类型/语义变化都必须发布新版本，旧版本继续保留。两栏高度一致，各自滚动。
- 数据表字段不依赖下游项目或 Token。新增业务字段必须先完成固定映射与后端验证，随后才进入该表字段目录。
- `新增下游项目`显示下游项目、可读取数据表、自动生成的长随机 Token ID 与店铺范围；新增表单必须先填写下游项目名称并勾选至少一张数据表和一个店铺，才能生成 Token。下游项目不创建或修改数据表。
- 新建成功后在项目列表长期显示 Bearer Token；配置同时保存明文和 SHA-256，运行鉴权仍使用 hash。历史 hash-only 项目显示“明文不可恢复”，不能伪造或猜测原 Token。
- 已有下游项目提供“修改读取范围”，只能重新勾选已发布数据表和 API 配置中已启用的店铺；项目名、Token ID、Bearer Token 不变。保存后提示重启生效，不影响本机同步或已有数据。
- 已有下游项目提供“接入说明”和下载操作。说明包含该项目授权的数据表、店铺 SID、当前明文 Token、固定 `CREATE TABLE` SQL 类型、快照/changes 示例和版本切换规则。
- 已有下游项目提供删除操作；删除只撤销该 Token，不删除数据表或业务数据，并提示重启后旧 Token 才正式失效。
- 店铺范围是 Token 的行级读取权限，只允许读取勾选店铺的数据，不影响本机同步，也不创建店铺分表；候选店铺只来自 API 配置中已启用的店铺。
- 数据表目录、字段和下游项目列表都来自固定管理 API；数据表 ID 只可从服务端目录选择，不从任意表名或用户输入动态推导。
- UI 永不创建、修改、删除 MySQL 表或列，不提供表名、SQL、path 编辑器或动态 schema builder。
- 加载失败显示「未能读取数据表配置」，空项目或空业务字段也必须保留完整页面骨架，不能伪装成功或隐藏切卡。
